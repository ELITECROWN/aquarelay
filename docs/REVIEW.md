# AquaRelay independent implementation review

Final scoped rereview: 2 October 2026. Reviewed against the complete supplied product brief and `docs/IMPLEMENTATION_PLAN.md`. This checkout has no Git history, so the review examined application source directly. Backend/frontend source, migrations, Compose/Docker definitions, tests and product documentation were read. Application source was not edited by the reviewer. Existing suites were not rerun; isolated in-memory reproductions inspected historical and stale behaviour without touching application data.

## Spec-compliance verdict

**The reviewed source implements the approved local MVP; final runtime acceptance remains qualified by the verification limits below.** No remaining P1/P2 source blocker was found in the final scoped rereview. The application has a persistent registry, interactive map, guided reports and evidence, scoped case workflow, reviewed/versioned imports, stored notifications, durable source and handoff jobs, standards payloads, offline drafts and generated share files. It retains the approved AquaRelay concept and the distinction between community observations, review decisions, documented actions and environmental conclusions.

The earlier privacy, event-ordering, history, provenance, import-reuse, profile, demo-label and contrast findings have been repaired in current source. Configuration-dependent services and standards subsets remain explicitly bounded. This verdict does not claim that PostgreSQL/Compose runtime, a live institutional recipient or a complete accessibility audit has passed.

## Code-quality verdict

**No remaining P1/P2 finding in the rereviewed code.** The modular monolith and relational model are appropriate for this local MVP. Organisation permissions, session/CSRF/origin restrictions, protected originals, public media derivatives, immutable source approvals, source provenance, replay controls and a durable SQL outbox provide meaningful foundations. Safe network adapters validate public addresses, pin checked IPs with the TLS hostname, revalidate redirects, limit credentials and bound request/response sizes.

The important frontend/backend contracts are now aligned. Account changes clear query/form state; closure category and explanation are separate; saved mappings return to the UI; historical snapshots exclude later conclusions; share labels derive from original report review decisions. Formatting the frontend has improved reviewability. PostgreSQL commit-order and PostGIS geometry behaviour have dedicated real-database regressions, but those remain unexecuted on this host.

## Other gaps and repairs checked

- **Duplicate suggestions:** the API applies observation type, a seven-day window and a one-kilometre coordinate rule. Where exact coordinates are absent it states that the match uses the same water body. Candidate reasons are visible; suggestions do not merge cases or invent review decisions.
- **Offline retry scope:** `OfflineDraftSync` mounts under the session provider across routes. Pending/failed account-scoped drafts retry on connectivity, use a running guard, recheck the server identity before submission and notify the report UI when local draft state changes.
- **Closure contract:** the server validates the supported outcome category separately from explanation, timestamp and supporting record. The UI sends and displays the category.
- **Institutional outgoing adapter:** server-configured recipient capabilities and durable FHIR delivery are implemented in `backend/app/integrations.py`. Recipient URLs and headers stay server-side. Delivery receipts are distinct from acknowledgement; an acknowledgement must match the declared contract, original idempotency key and explicit receipt. Missing configuration leaves export available and delivery unavailable. Seven focused regressions cover configuration, credentials, job/replay/failure/recovery, acknowledgement binding and bounded safe transport.
- **Source ageing:** connector health propagates into public source/passport state. The isolated ageing reproduction returns stale in Integrations and `Data unavailable or outdated` in the passport.
- **Historical merge/reopening:** snapshot merge trails, targets and reopening requests are filtered by the cutoff, preventing later workflow changes appearing in the historical view.
- **Public source safety:** unsupported URL schemes and recognised query credentials are excluded/redacted. Supporting public sources remain readable without connector-manager access.
- **Share honesty:** `ShareModal.tsx` and `shareLabels.ts` use original report review states, retain explicit unreviewed/mixed/unavailable labels, and condition synthetic watermarks on record flags. Action cards have a separate organisation-submitted action label. Focused tests inspect the canonical review mapping.
- **Governed evidence:** protected originals, public metadata-free derivatives, authorised redaction/deletion and audit records are implemented. Concern intake persists a request; it does not invent a moderation outcome. No full moderation console or automatic public-text moderation is claimed by this review.
- The root reports the test database isolation and share-dialog canvas issue repaired; these were not independently rerun by this reviewer.

## Deliberately not treated as defects

- The approved brief excludes pollution prediction, water-safety/trust scoring, causal diagnosis, chatbot, patient/hospital records, blockchain, payment and leaderboards. Their absence preserves scope.
- Paid AI, email/push, basemap/geocoder credentials and production institutional recipients are configuration-dependent. Explicit unavailable states and deterministic rules are acceptable stated fallbacks.
- Real partnerships, official contacts, social handles or real environmental conclusions must not be fabricated to fill a demo.
- No destructive demo-reset endpoint exists, so there is no implemented reset action requiring a confirmation flow.
- The API still performs some per-record queries and Haversine calculations. PostGIS indexes are created but those registry reads do not yet use them. Large-registry optimisation and a separate service fleet are outside this local acceptance scope.
- Additional tab semantics and stronger domain types would be useful maintenance work; they do not override the concrete findings and verification limits above.

## Final browser-QA follow-up: stream coalescing and map fallback

This scoped follow-up read the final browser fixes in `src/App.tsx` and `src/pages.tsx`, the public stream implementation and the installed TanStack Query implementation. No product source was edited and no full suite was rerun.

- **Public cursor/privacy: no new finding.** The stored value is only a validated numeric public-event cursor. The backend stream is public and publishes the same public records across accounts; the cursor neither contains personal data nor restores a personal query cache. Existing identity cancellation/cache clearing remains effective. EventSource's reconnect ID is accepted by the backend, and storage failures retain connection-local reconnect behaviour.
- **Coalescing race (R9 / P2): resolved in the final source.** The initial `cancelRefetch:false` implementation could reuse an older in-flight GET and clear a newer event invalidation. The current refresh checks active queries already fetching, awaits the uncancelled invalidation, and schedules one trailing coalesced refresh when an older fetch existed or an event arrived during the refresh. Its disposed flag prevents trailing work after teardown. A narrow check extracted/transpiled the actual current refresh block and exercised the installed QueryClient/QueryObserver: 1,000 updates during an older fetch produced exactly two requests and the latest value; an update during refresh also produced two requests and the latest value; disposal before settlement prevented the second request. The added browser regression deliberately delays a stale 99-case snapshot while 1,000 events arrive, then requires a second request and a corrected card. Its full browser-run result belongs to the root ledger. No new source regression or account-privacy finding was identified; the earlier no-open-P1/P2 source verdict is restored.
- **Map-only error boundary: no new finding.** The boundary isolates React map/lazy-import failures, retains the page's records, presents an accessible status, observes connectivity and offers reload after reconnect. A rejected React.lazy import is cached, so full-page reload is a valid recovery mechanism. It should not be described as automatically reloading only the map; the current button reloads the page. Existing persistent report drafts are independent of this boundary. Runtime map/network errors outside React remain the map component's own responsibility.

This follow-up does not change the PostgreSQL/Compose, external-recipient, standards-conformance or full-accessibility evidence limits above. The root's final browser ledger remains authoritative for observed browser behaviour.
