# AquaRelay 3–5 minute demonstration

Before presenting: start the API/frontend (or Compose), open two independent browser sessions, and log the first in as the demo manager and the second as the citizen. All coordinates, records and organisations are fictional. Say **“Demo scenario”** whenever referring to the staged history or synthetic new evidence.

1. **0:00–0:40 — Find a place.** Open Explore. Pan/zoom the real MapLibre map, select Demo Reedwater Lake using the map or list, and open its passport. Explain that the synthetic demo layer is not real geography and open-case counts do not assess condition.
2. **0:40–1:10 — Preserve the history.** Open Incidents → Demo shoreline waste observation. Inspect the dated cleanup and separate follow-up, then the recorded closure. Explain that completion of an activity does not prove ecosystem recovery.
3. **1:10–2:00 — Connect source records.** As manager, open Data sources → Import a file. Download/use `fixtures/demo-ngo-missing-unit.xlsx`. Preview the source and transform it with the temperature unit absent. Inspect the actual quarantine reasons. Edit mapping: temperature = degC, pH = dimensionless (1), source timezone = Asia/Kolkata. Keep row-specific site matching. Review, approve and inspect the persisted counts. Open Reedwater → Monitoring to see 24.5 Cel and 25 Cel with source IDs. Reimport using the same dataset identity to demonstrate duplicates.
4. **2:00–2:45 — Report and follow.** As citizen, follow Reedwater. Open Report. Select Reedwater, an observed time, dead/distressed fish, a clearly synthetic original description with an estimated count range, and a labelled demo illustration. Review related-case candidates. Choose to add to an existing open case or submit separately. Submit and show the real report/case IDs and saved evidence. Watch the public map in the other session receive a committed update.
5. **2:45–3:45 — Document a response.** As assigned manager, open the incident. Acknowledge, investigate, record an action and explicit follow-up. Try closure without a supporting record to show server requirements; then select “Closed without a confirmed cause” and supply an explanation, completion date and traceable action/evidence. Say “Demo scenario”: no real field work took place during this presentation. In the citizen session, open Updates and inspect the stored notification and its underlying case link. New evidence can request reopening without rewriting the earlier closure.
6. **3:45–4:15 — Share a factual snapshot.** Open Share update. Inspect timestamp, source/review label and synthetic watermark. Download square or story PNG and edit the caption. Explain that exported cards remain dated snapshots; the permalink contains the current record. A local deployment has no public QR destination.
7. **4:15–4:45 — Standards and receipt.** Open Data sources, select Reedwater and export FHIR/SensorThings. Send a FHIR payload to the local demo receiver. Open the persisted receipt and show structural validation plus `acknowledged:false`. Delivery is not organisational acknowledgement, and this endpoint is not a hospital or municipality.
8. **4:45–5:00 — Honest failure and recovery.** Open the labelled local demo scenario connector. Use its failure simulation and test/sync: a real persisted failure, last attempt, stale/error context and retry history appear. Restore the demo source and safely retry after backoff; replay preserves source IDs. Remote production endpoints still require real configuration.

Optional offline extension: in browser network controls, go offline while a signed-in report is open, save pending text/media, inspect the local pending label, reconnect and use Sync now. Show the server acknowledgement before calling it submitted. Local drafts belong to the signed-in account.
